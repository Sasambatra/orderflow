# Измерения HTTP-нагрузки

**Русский** · [English](benchmarks.en.md)

Дата: 30 октября 2026 года. Это измерения локального учебного стенда, без обещаний промышленного SLA.

## Стенд и методика

Python 3.14.4, PostgreSQL 18.6 (Ubuntu 18.6-0ubuntu0.26.04.1), Redis 8.10.3.
WSL2/Linux, AMD Ryzen 5 7640HS, 12 логических CPU, около 7,36 GiB RAM в WSL.
API: один Uvicorn-процесс, синхронные маршруты, SQLAlchemy pool 5 + max_overflow 5.
Celery: два процесса worker и один Beat. Контейнерных лимитов нет.
HTTP идёт через loopback без TLS. Генератор нагрузки и все сервисы используют одну машину.

Для каждой параллельности выполнены три прогона по 500 созданий заказов с разными UUIDv4 и достаточным запасом, затем по 500 чтений каталога.
Для чтения выполнялись 10 запросов прогрева перед каждым прогоном; создание измерялось на уже запущенном API без отдельной партии прогрева.
Другие pytest-проверки одновременно с итоговыми прогонами не запускались; в начале c20 параллельно завершалась установка зависимостей в проверочное окружение. Демо-товары и рабочие фоновые задачи остаются частью стенда.

Каждый набор завершён без transport errors, неожиданных 4xx/5xx и нарушений SQL-инварианта reserved = сумма active reservations.
После обоих наборов проверено on_hand >= reserved >= 0. Всего измерено 3000 созданий и 3000 чтений.

Пиковый RSS API измерялся с шагом 50 ms, это не память всего стека:

- Concurrency 20: 112472 KiB.
- Concurrency 50: 130264 KiB.

При росте concurrency увеличивается ожидание соединения и блокировки горячего SKU. Эти числа не характеризуют нагрузку реальных покупателей через интернет.
Измерялся исходный код коммита `942ba88`. Полный commit SHA, дата и source SHA-256 сохранены в JSON; последующий коммит обновляет только отчёты и документацию.

## Последняя единица

Отдельный сценарий `scripts/benchmark.py`: 20 одновременных HTTP-запросов с разными ключами, одна единица — один 201 и 19 ожидаемых 409. Это проверка корректности, не измерение пропускной способности.
Вариант с одним ключом проверяется тестом `test_twenty_retries_one_order`.

## Воспроизведение

```bash
make seed
make benchmark
.venv/bin/python scripts/load_test.py --requests 500 --concurrency 20 --runs 3
.venv/bin/python scripts/load_test.py --requests 500 --concurrency 50 --runs 3
```

API, PostgreSQL, Redis, worker и Beat должны работать. Не запускайте оба load_test одновременно.
В Docker скрипт можно запустить через `docker compose exec api python scripts/load_test.py`, если он включён в development image; в runtime image доступны demo.py и benchmark.py.

Сырые локальные данные: output/. Очищенные публикуемые отчёты: [c20](benchmarks/load-c20.json), [c50](benchmarks/load-c50.json), [last unit](benchmarks/last-unit.json).
